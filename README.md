# Sifora Launcher

Лёгкий лаунчер Minecraft на **Tauri 2 + Rust + Vue 3 + TypeScript + Vite + Tailwind CSS 4**.

Это **первый этап**: главный экран запуска, выбор версии из официального манифеста
Mojang, настоящая установка и запуск Minecraft, безопасная система тем с ИИ-композитором
и фундамент изолированных игровых сборок.

## Как пользоваться ИИ-дизайнером тем

Тема создаётся в разделе **Оформление → Дизайнер тем**: опишите словами, как
должна выглядеть, и нажмите «Создать тему».

Два режима, переключаются ссылкой **«Своя модель»**:

1. **Встроенный композитор** *(по умолчанию)* — бесплатный, работает без
   интернета и без ключей. Это код в `src-tauri/src/theme/generate.rs`: он
   разбирает описание, достаёт из него цвет, настроение, форму, шрифт,
   движение и декор, и **композирует** новую тему по правилам гармонии. Выбор
   из готовых шаблонов не происходит — комбинация, которой не было, тоже
   получается.
2. **Своя модель** — любой OpenAI-совместимый адрес (`https://…/v1`), название
   модели и ключ. Всё это вводится в приложении; ключ хранится в
   `%APPDATA%\dev.sifora.launcher\ai.local.json`, который не попадает в репозиторий.
   Если модель недоступна или её ответ не проходит проверку, лаунчер молча
   возвращается к встроенному композитору и честно пишет об этом в интерфейсе.

### Подключение бесплатной модели

Копировать адрес из браузера не нужно: в разделе **Оформление → «Своя модель»**
есть кнопки готовых провайдеров.

| Провайдер | Адрес | Ключ |
|---|---|---|
| **OpenRouter** | `https://openrouter.ai/api/v1` | бесплатный, без карты |
| Groq | `https://api.groq.com/openai/v1` | бесплатный, без карты |
| Google AI Studio | `https://generativelanguage.googleapis.com/v1beta/openai` | бесплатный |
| Локально (Ollama) | `http://localhost:11434/v1` | не нужен |

**Бесплатные модели у OpenRouter — до 50 запросов в сутки** (1000 после разового
пополнения на $10; порог сохраняется навсегда, даже когда баланс снова нулевой).
Потолок 20 запросов в минуту не поднимается никогда. Для дизайнера тем этого
хватает с большим запасом: тема создаётся вручную, а не потоком.

Список моделей **не зашит в программу** — он запрашивается у самого провайдера
через его же `/models`, поэтому не устаревает. Признак «бесплатная» берётся из
цены за токены, которую сообщает провайдер; модели, о цене которых провайдер
молчит, идут в группу «Остальные», а не выдаются за бесплатные. Список
кэшируется на 10 минут, кнопка «Обновить список» сбрасывает кэш.

Кнопка **«Проверить связь»** делает один короткий запрос и говорит словами, что
не так: «Ключ не принят», «Модель занята — бесплатные модели часто в очереди,
повторите через минуту», «Модель не найдена по этому адресу». Код ответа в
интерфейс не выносится.

Адрес обязан быть HTTPS. Исключение — `localhost` и `127.0.0.1`: там трафик не
выходит из машины, и запирать локальную модель не от чего.

Любой результат сначала показывается как предпросмотр — «Применить» или
«Отмена». Тема может менять только внешний вид: цвета, форму, шрифт, анимацию,
фон и **раскладку** — порядок меню, скрытые разделы, кнопки на главном экране.
Ни одна тема не может добавить функцию, которой в лаунчере нет.

## Требования

- Windows 10/11 (x64) + WebView2 (предустановлен в Windows 11)
- Node.js 20.19+ / 22.12+
- Rust stable (`rustup`) с тулчейном `stable-x86_64-pc-windows-msvc`
- Visual Studio Build Tools 2022 (или новее) с компонентами «Разработка классических приложений на C++»

## Сборка и запуск

```bash
npm install
npm run tauri:dev      # запуск в режиме разработки
npm run tauri:build    # релизная сборка + NSIS-установщик (~2 МБ)
```

Отладочная сборка тоже собирается с рабочим интерфейсом — просто включите
протокол production, иначе бинарник ждёт Vite-сервер на `localhost:1420`:

```bash
cd src-tauri && cargo build --features tauri/custom-protocol
```

Консольное окно не появляется ни в одной сборке (`#![windows_subsystem]`).

Отдельные команды:

```bash
npm run dev            # только фронтенд (в браузере, без Rust)
npm run typecheck      # vue-tsc
npm run build          # проверка типов + сборка фронтенда
cd src-tauri && cargo test   # 121 unit-тест бэкенда
```

Артефакт установщика: `src-tauri/target/release/bundle/nsis/`.

### Почему так

- **Рендерер не имеет прав.** Он не читает файлы, не ходит в сеть, не запускает
  процессы и не обращается к ACL Tauri. Всё привилегированное — команда Rust с
  собственной валидацией.
- **Нет фоновых процессов.** Приложение — один процесс; сетевые запросы
  асинхронные, логи пишутся в кольцевой буфер в памяти.
- **Нет `Electron`, нет Node в рантайме.** WebView2 системный, в корзину
  попадает только JS/CSS и нативный бинарник.

## Безопасность тем и ИИ

Это часть продукта, а не украшение, поэтому она описана подробно.

### Что тема **может**

Только визуальные параметры: цвета, фон, градиенты, прозрачность, шрифты,
отступы, радиусы, оформление компонентов, декоративные слои, переходы и
анимации.

И **раскладку** — то, что уже существует в лаунчере:

| Просьба словами | Что происходит |
|---|---|
| «крупные кнопки» | масштаб интерфейса и шаг сетки |
| «перенеси настройки на главный экран» | кнопка на экране запуска + раздел первым в меню |
| «без анимаций» | переходы выключаются, финальное состояние сохраняется |
| «пружинная анимация» | характер движения, а не только скорость |
| «круглые углы» / «острые углы» | характер углов: скругление, пилюля, почти квадрат |
| «прописные буквы» | регистр подписей на органах управления |
| «убери о лаунчере» | раздел уходит из меню |
| «покажи всё» | скрытое возвращается |

Это разбирает **набор правил** (`theme/layout.rs`), а не языковая модель:
словарь маленький и закрытый, поэтому ответы точные, мгновенные, бесплатные и
работают офлайн. Модель подключается как второй вход в ту же схему — она получает
тот же закрытый список названий и физически не может назвать то, чего в лаунчере
нет.

### Что тема **не может**

| Ограничение | Как обеспечено |
|---|---|
| Выполнять JS / Rust / HTML / CSS | В схеме нет ни одного поля для кода |
| Добавлять новые кнопки и действия | `Layout` содержит только перечисления существующих разделов и умений; чужое имя **не декодируется вообще**, а не чинится молча (`a_theme_cannot_invent_a_capability`) |
| Спрятать раздел навсегда | Порядок меню пересобирается в полную перестановку с обеих сторон, «Запуск» не убирается |
| Инъекция через CSS | `Color` принимает только hex-литерал и **пересериализуется** в каноническую форму |
| Инъекция через `url()` | Фоновые изображения — только локальные файлы, скопированные Rust в папку приложения |
| Доступ к файловой системе / сети | У рендерера нет таких возможностей вообще |
| Обход CSP | `default-src 'self'`, `object-src 'none'`, `frame-src 'none'`, `base-uri 'none'` |
| Изменение разрешений Tauri | `capabilities/default.json` собирается на этапе build и не зависит от данных |
| Отправка ключа на новый адрес | Ключ подставляется, только если запрошенный адрес совпадает с сохранённым |
| Удаление/обход проверок | Валидация обязательна на записи, на чтении и перед применением |

### Конвейер темы

```
описание пользователя
   ↓  фиксированный системный промпт (код, не данные)
модель / локальный композитор
   ↓  ответ = НЕДОВЕРЕННЫЕ входные данные
coerce_into_schema()   ← поле-в-поле, только известные ключи и типы
   ↓
validate_theme()       ← диапазоны, контраст, целостность, перестановка меню
   ↓  ThemeSpec: только цвета, числа и перечисления
themeVariables()       ← CSS custom properties на :root
   ↓
data-атрибуты          ← углы, характер движения, регистр, размещение
```

Раскладка проходит тот же путь, что и цвета: то же поле-в-поле слияние, та же
валидация, те же `data-`атрибуты. Она не получает отдельного, «более доверенного»
входа.

Ключевые свойства, покрытые тестами в `src-tauri/src/theme/`:

- `color.rs` — `url(javascript:…)`, `expression()`, `var()`, CSS-инъекция отвергаются;
- `provider.rs` — `coercion_drops_unknown_and_hostile_fields`, `coercion_can_never_set_a_remote_background_image`,
  `prompt_injection_in_the_request_cannot_leave_the_tag`, `api_key_is_never_serialised_to_the_view`,
  `a_model_cannot_invent_a_section_or_shortcut`, `the_config_crosses_the_wire_in_camel_case`;
- `catalog.rs` — `loopback_http_is_allowed_for_a_local_model_server`,
  `https_is_allowed_and_remote_http_is_not`, `free_models_are_identified_from_pricing_and_sorted_first`;
- `layout.rs` — `built_layouts_are_complete_and_bounded`, `a_theme_can_hide_sections_and_undo_it`;
- `generate.rs` — `markup_in_the_prompt_cannot_leak_into_the_theme`;
- `validate.rs` — `a_theme_cannot_invent_a_capability`,
  `an_incomplete_menu_order_is_repaired_rather_than_trusted`;
- недоступный акцент и нечитаемый текст исправляются, а не применяются.

### Локальный композитор (бесплатно, офлайн)

`theme/generate.rs` разбирает описание, извлекает цвет, настроение, форму,
типографику, движение и декор, затем **композирует** новую тему по правилам
гармонии. Это не выбор из шаблонов:

> «тёмная фиолетовая тема со стеклянными панелями, зелёным акцентом и сеткой»
> → фиолетовые поверхности, зелёный акцент, стеклянные карточки, узор-сетка.

Такая комбинация не существует ни в одном встроенном пресете.

### Независимая модель (необязательно)

Пользователь сам указывает адрес любого OpenAI-совместимого endpoint, модель и
ключ. Они хранятся в `ai.local.json` **в папке данных приложения** (вне
репозитория, `.gitignore`), ключ никогда не возвращается в рендерер. Адрес обязан
быть HTTPS; исключение сделано только для `localhost` и `127.0.0.1`, где трафик
не покидает машину. Если модель недоступна или ответ не проходит проверку,
лаунчер создаёт тему локальным композитором и честно сообщает об этом.

Готовые провайдеры (OpenRouter, Groq, Google AI Studio, локальный Ollama) — это
**константы в коде** (`theme/catalog.rs`), а не пользовательские данные: рендерер
не может ни изменить их, ни добавить свою запись. Список моделей приходит от
самого провайдера; ключ подставляется в запрос к `/models` только если
запрошенный адрес совпадает с сохранённым, — рендерер не может заставить лаунчер
отправить ключ на новый адрес, которого пользователь не вводил.

## Запуск Minecraft

1. `version_manifest_v2.json` загружается с Mojang и кэшируется на 6 часов.
2. Документ версии (и вся цепочка `inheritsFrom`) кэшируется локально.
3. Скачиваются клиент, библиотеки и ресурсы с проверкой SHA-1; несовпадение
   удаляет файл и начинает заново.
4. Незавершённые загрузки лежат в `.part` и продолжаются с места обрыва
   (`Range:`).
5. Параллельность ограничена: 8 для ресурсов, 4 для библиотек, 1 для клиента.
6. Java подбирается так, чтобы её версия была **не меньше** требуемой, с
   приоритетом точного совпадения; при отсутствии скачивается Temurin JRE.
7. Аргументы собираются в `Vec<String>` и передаются ОС списком — сборки
   командной строки не происходит. Опасные флаги (`-javaagent`, `-XX:OnError=`,
   `-Xbootclasspath`, `--add-opens` и т. п.) отбрасываются.

### Аутентификация

Первый этап работает **в автономном режиме**: ник проверяется локально, UUID
выводится по алгоритму `OfflinePlayer:<name>` (как в ванильном клиенте).
Учётные данные Mojang не запрашиваются, не хранятся и не передаются.

## Что подготовлено для второго этапа

Без реализации интерфейса и логики, только структуры:

- `mc::instances::InstanceMeta.mods` — `ModLoader` (`none/fabric/forge/quilt/neoforge/optifine`),
  версия загрузчика, флаг включения; свой `mods/` и `config/` внутри каждого instance;
- `commands::launch` — `list_instances`, `update_instance_settings`, `delete_instance`,
  `instance_paths` (готовы к копированию и настройке сборок);
- `commands::theme` — `generate_theme`, `preview_theme`, `apply_theme`, `undo_theme`,
  `reset_theme`, `derive_theme`, `validate_theme_command`;
- `capabilities` и CSP не содержат ничего, что помешало бы добавить
  fs/shell-плагины позже, — но и не содержат их сейчас.

## Секреты и приватность

В репозитории **нет** ключей API, паролей, токенов и профилей.
`.gitignore` исключает `*.local.json`, `.env`, `*.pem`, `*.key`, `profiles/`,
`instances/`. Если вы добавляете endpoint для ИИ-модели, настройте его в
приложении — файл `ai.local.json` создастся сам и в репозиторий не попадёт.
