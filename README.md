# Sifora Launcher

Лёгкий лаунчер Minecraft на **Tauri 2 + Rust + Vue 3 + TypeScript + Vite + Tailwind CSS 4**.

Один процесс, системный WebView2, никакого Electron и Node в рантайме. Вся
привилегированная логика — в Rust: рендерер только рисует и вызывает команды.

## Сборки

Сборка — это отдельная папка с игрой, своим набором модов и своими настройками.
Одно и то же имя версии может встречаться в нескольких сборках, и они не мешают
друг другу: у каждой свой `.minecraft`, свой `mods/`, свой `config/`.

Раздел **Сборки**:

1. **Создать сборку** — имя, значок (по желанию), версия Minecraft, загрузчик и
   его версия, объём памяти, размер окна, аргументы JVM и игры.
2. **Играть** — установить недостающее и запустить.
3. **Моды** — открыть браузер модов Modrinth уже в контексте этой сборки.
4. **Папка** — открыть игровую директорию в проводнике.

Выбор версии вынесен в сборку: чтобы играть в 1.12.2, нужно сначала создать
сборку с этой версией. На главном экране версия не выбирается — там выбирается
сборка.

### Загрузчики

| Загрузчик | Как ставится |
|---|---|
| Fabric | профиль-манифест с сервера Fabric, без установщика |
| Forge | официальный установщик запускается без окна (`--installClient`) |
| NeoForge | тот же установщик, отдельный список версий |

Идентификатор установленного профиля лаунчер определяет, сравнивая содержимое
`versions/` до и после работы установщика, — а не угадывая по имени файла.
Результат записывается в сборку.

## Моды (Modrinth)

Поиск идёт через официальный API Modrinth, все запросы делает Rust:

- поиск по названию с задержкой 350 мс, сортировка, постраничный вывод;
- фильтры: категории, загрузчик, версия Minecraft — по умолчанию подставляются
  из самой сборки (если она на Fabric, показываются только Fabric-версии);
- карточка мода: описание, автор, загрузки, список версий и файлов;
- установка кладёт `.jar` в `mods/` нужной сборки.

Скачивание разрешено только с хостов из белого списка (CDN Modrinth, GitHub,
Forge CDN), имя файла обязано быть простым именем `.jar`, идентификатор проекта
не может быть `.`, `..` или содержать разделители пути. Ключ API для Modrinth не
нужен. Моды, положенные в папку вручную, помечаются в списке как «вручную», а не
выдаются за установленные лаунчером.

## Темы

Тема — это закрытая схема: цвета, числа и перечисления. **Генератора тем нет** ни
офлайнового, ни через модель: тема делается руками.

Раздел **Оформление**:

- **Галерея** — 13 встроенных тем и все свои: применить, изменить, выгрузить в
  файл, удалить, отменить последнее, вернуться к исходной.
- **Редактор** — палитра (13 цветов с прозрачностью), форма и радиусы,
  типографика, оформление компонентов, фон и декор, движение, расположение
  разделов меню и кнопок на главном экране. Изменения показываются сразу;
  сохраняются — только по кнопке.
- **Экспорт / импорт** — тема выгружается в `.sifora-theme.json` и читается
  обратно. Файл при импорте получает новый идентификатор: он не может
  перезаписать существующую тему или выдать себя за встроенную.

Правка встроенной темы создаёт свою копию — встроенную изменить нельзя.

## Требования

- Windows 10/11 (x64) + WebView2 (предустановлен в Windows 11)
- Node.js 20.19+ / 22.12+
- Rust stable (`rustup`) с тулчейном `stable-x86_64-pc-windows-msvc`
- Visual Studio Build Tools 2022 (или новее) с компонентами «Разработка классических приложений на C++»

## Сборка и запуск

```bash
npm install
npm run tauri:dev      # запуск в режиме разработки
npm run release        # всё: проверки, тесты, приложение, NSIS-установщик
npm run release:fast   # только приложение, без установщика (быстрее)
npm start              # запустить уже собранное приложение
```

Отладочная сборка тоже собирается с рабочим интерфейсом — просто включите
протокол production, иначе бинарник ждёт Vite-сервер на `localhost:1420`:

```bash
cd src-tauri && cargo build --features tauri/custom-protocol
```

Консольное окно не появляется ни в одной сборке (`#![windows_subsystem]`).

Отдельные команды:

```bash
npm run dev            # только фронтенд (в браузере, без Rust)
npm run typecheck      # vue-tsc
npm run test:rust      # тесты бэкенда
npm run check          # и то, и другое
```

Артефакт установщика: `src-tauri/target/release/bundle/nsis/`.

### Почему так

- **Рендерер не имеет прав.** Он не читает файлы, не ходит в сеть, не запускает
  процессы и не обращается к ACL Tauri. Всё привилегированное — команда Rust с
  собственной валидацией.
- **Нет фоновых процессов.** Приложение — один процесс; сетевые запросы
  асинхронные, логи пишутся в кольцевой буфер в памяти.
- **Нет `Electron`, нет Node в рантайме.** WebView2 системный, в корзину
  попадает только JS/CSS и нативный бинарник.

## Безопасность тем

Это часть продукта, а не украшение, поэтому она описана подробно.

### Что тема **может**

Только визуальные параметры: цвета, фон, прозрачность, шрифты, отступы, радиусы,
оформление компонентов, декоративные слои, переходы и анимации.

И **раскладку** — то, что уже существует в лаунчере: порядок разделов меню, какие
разделы скрыты, какие кнопки показаны на главном экране, размещение, характер
углов и движения, регистр подписей. Тема может решить, *где* живёт функция; она не
может создать новую.

### Что тема **не может**

| Ограничение | Как обеспечено |
|---|---|
| Выполнять JS / Rust / HTML / CSS | В схеме нет ни одного поля для кода |
| Добавлять новые кнопки и действия | `Layout` содержит только перечисления существующих разделов и умений; чужое имя **не декодируется вообще**, а не чинится молча (`a_theme_cannot_invent_a_capability`) |
| Спрятать раздел навсегда | Порядок меню пересобирается в полную перестановку с обеих сторон |
| Инъекция через CSS | `Color` принимает только hex-литерал и **пересериализуется** в каноническую форму |
| Инъекция через `url()` | Фоновые изображения — только локальные файлы, скопированные Rust в папку приложения |
| Доступ к файловой системе / сети | У рендерера нет таких возможностей вообще |
| Обход CSP | `default-src 'self'`, `object-src 'none'`, `frame-src 'none'`, `base-uri 'none'` |
| Изменение разрешений Tauri | `capabilities/default.json` собирается на этапе build и не зависит от данных |
| Подмена темы файлом при импорте | Идентификатор из файла отбрасывается, имя дедуплицируется, спецификация проходит ту же валидацию |
| Удаление/обход проверок | Валидация обязательна на записи, на чтении и перед применением |

### Конвейер темы

```
тема (правка в редакторе или импортированный файл)
   ↓  закрытая схема: неизвестное поле — ошибка, а не «пропустим»
serde + deny_unknown_fields
   ↓
validate_theme()       ← диапазоны, контраст, целостность, перестановка меню
   ↓  ThemeSpec: только цвета, числа и перечисления
themeVariables()       ← CSS custom properties на :root
   ↓
data-атрибуты          ← углы, характер движения, регистр, размещение
```

Ключевые свойства, покрытые тестами в `src-tauri/src/theme/`:

- `color.rs` — `url(javascript:…)`, `expression()`, `var()` и CSS-инъекция
  отвергаются;
- `model.rs` — неизвестное поле в теме не декодируется;
- `validate.rs` — `a_theme_cannot_invent_a_capability`,
  `an_incomplete_menu_order_is_repaired_rather_than_trusted`;
- `store.rs` — экспорт и импорт идут через ту же валидацию, что и обычная запись;
- недоступный акцент и нечитаемый текст исправляются, а не применяются.

## Запуск Minecraft

1. `version_manifest_v2.json` загружается с Mojang и кэшируется.
2. Документ версии (и вся цепочка `inheritsFrom`) кэшируется локально; битый
   кэш перечитывается один раз, а не считается смертельным.
3. Скачиваются клиент, библиотеки и ресурсы с проверкой SHA-1; несовпадение
   удаляет файл и начинает заново. Объекты ресурсов берутся с
   `resources.download.minecraft.net`, а не с адреса индекса.
4. Незавершённые загрузки лежат в `.part` и продолжаются с места обрыва
   (`Range:`). Постоянные ошибки (404, 403) не повторяются — только временные.
5. Параллельность ограничена: 8 для ресурсов, 4 для библиотек, 1 для клиента.
6. Java подбирается так, чтобы её версия была **не меньше** требуемой, с
   приоритетом точного совпадения; при отсутствии скачивается Temurin JRE, если
   это разрешено настройкой.
7. Аргументы собираются в `Vec<String>` и передаются ОС списком — сборки
   командной строки не происходит. Опасные флаги (`-javaagent`, `-XX:OnError=`,
   `-Xbootclasspath`, `--add-opens` и т. п.) отбрасываются.

### Аутентификация

Работает **автономный режим**: ник проверяется локально, UUID выводится по
алгоритму `OfflinePlayer:<name>` (как в ванильном клиенте). Учётные данные Mojang
не запрашиваются, не хранятся и не передаются.

## Секреты и приватность

В репозитории **нет** ключей API, паролей, токенов и профилей. `.gitignore`
исключает `*.local.json`, `.env`, `*.pem`, `*.key`, `profiles/`, `instances/`.
Лаунчер не читает никаких ключей из окружения: Modrinth работает без ключа, а
сетевые адреса заданы в коде.
